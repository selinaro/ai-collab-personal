# Beschreibung folgt dem Wert, nie umgekehrt

Passt eine Description (Variable, Komponente, Doku-Satz) nicht zum tatsächlichen Wert, dann wird **der Text korrigiert**. Nie vorschlagen, einen Wert anzupassen, damit er zu einer ungenauen oder falschen Beschreibung passt — auch nicht als gleichwertige Option «entweder Satz streichen oder Wert angleichen».

**Why:** Selina, 10.11.2026: «Es sollte nie ein Wert auf Basis einer ungenauen/falschen Beschreibung angepasst werden. Lieber den Text anpassen. Der Effekt ist unverhältnismässig.» Anlass: Description von `*Font-Colors/Status/neutral` sagte «Same source as *Icon-Colors/default», der Wert war aber bewusst eine andere Stufe; ich hatte «Wert angleichen» als Option genannt. Ein Wert wirkt auf jede Verwendung, ein Text nur auf sich selbst.

**How to apply:** Bei jedem Befund «Beschreibung ≠ Wert» direkt einen korrigierten Textvorschlag liefern. Eine Wertänderung nur vorschlagen, wenn es einen eigenen sachlichen Grund gibt (Kontrast, Konsistenz der Rolle) — dann getrennt begründen, mit «vorher → nachher» ([[aenderungen-ausweisen-und-belegen]]).
